Building AssaultCube on Apple Silicon
=====================================

Install Xcode and select it as the active developer directory. Install the
native Homebrew dependencies once:

    brew install sdl2 sdl2_image libogg libvorbis

From the repository root, run:

    ./build-macos.sh
    ./run-macos.sh

The game and launcher targets build arm64 in all configurations. SDL2,
SDL2_image, Ogg, Vorbis and their dependencies come from native Homebrew
libraries, replacing the old Intel-only frameworks. Current Homebrew SDL2
uses sdl2-compat, which loads SDL3 at runtime; SDL3 is also bundled.

The build phase embed_native_libraries.py copies the full library dependency
chain into the app, rewrites load paths and applies ad-hoc signatures. It
rejects binaries that are not arm64-only. The resulting app uses no Homebrew
paths at runtime and does not require Rosetta. Xcode builds use /opt/homebrew
by default; build-macos.sh passes the active Homebrew prefix explicitly.

The app is built at build/Products/Release/assaultcube.app. The run script
starts the executable from the repository root so it can find config/, bot/
and packages/. Player settings are stored in ~/.assaultcube/v1.3.

The project deployment target is macOS 12; Homebrew dependencies may require
a newer macOS version, depending on the installed bottles.

Release-Deployment additionally creates a DMG containing the launcher and
game data. Normal Release builds skip this packaging phase.
